# Upload Reel

Complete the requested Instagram upload using existing approved media. User instructions override these defaults. Creating or invoking this skill does not grant standing permission to publish future content.

## Prepare or resume

- Use connected Chrome and its current browser documentation. Discover the live browser and tabs, then verify the signed-in account before changing anything. Default to **@dinke4leetcode** unless the user names another account. Browser and tab IDs from past runs are not reusable evidence of a connection.
- Locate the approved final MP4, matching cover, and posting caption or transcript. For this user's productions, look under `C:/Users/utkarsh/Desktop/Development/Reels/<topic>/out/`. Prefer explicit paths and the latest approved production handoff over filename guesses.
- Check the profile for an existing reel of the same content before uploading. If a composer or draft already exists, inspect and continue it rather than starting another upload.
- When the user has selected the video, set its crop or added its cover, preserve that work. Identify the current stage from the page, not assumptions about where an earlier turn stopped.

## Video and cover

- Read the browser's file-upload guidance before selecting files. Use its supported file chooser with absolute local paths.
- Preserve **9:16 portrait framing**, narration and burned-in captions. Check the preview for unwanted cropping, cut-off text, or horizontal framing. Do not trim or re-encode the approved video as part of an upload.
- Upload the matching existing cover when needed and inspect its wording and framing. Retain a user-selected cover. Do not call an automatically selected frame the requested custom cover. If no cover exists, resolve that missing asset without inventing a separate creative task.
- If automatic file selection is blocked, follow the browser's documented troubleshooting. Give the exact file path, leave the appropriate control ready, and ask the user to select that file manually. After the user responds, inspect the composer and resume it without re-uploading.

## Caption and settings

- Reuse approved caption text. Otherwise write a concise topic-specific hook, an accurate explanation or key takeaway, a useful save/follow invitation, and relevant hashtags. Use the actual transcript or production brief; do not invent claims.
- For Dinke4Leetcode algorithm explainers, favor beginner-friendly **DSA** wording. Mention C++ or another language where it accurately describes the video. A channel follow line can mention DSA, LLD and HLD without claiming that every reel covers all three.
- Instagram captions and hashtags are the posting text; do not look for YouTube title, search-tag or Education fields.
- Skip manual timestamps, chapter mapping, subtitle alignment and SRT editing. Preserve the captions already present in the video.
- Leave location, tagged people, collaborators, cross-posting and unrelated account settings unchanged unless requested. Answer AI or other disclosure questions from actual production facts and the current prompt; do not infer realistic AI footage merely from a cartoon style.

## Publish or schedule

- An explicit request to upload/post the reel authorizes completing that routine publication to the identified account. Honor requests to prepare only, save a draft or schedule instead. A caption-only edit does not authorize publishing an unpublished draft.
- Before Share, verify the account, selected media, portrait preview, cover and caption. If this authorization is already clear, do not request it again.
- Use scheduling only when requested and supported by the current interface. Resolve the absolute date and time in **Asia/Kolkata (IST, UTC+05:30)** unless another zone is specified. Show the resolved time, verify the selected zone, and request a replacement for a time that has passed. Do not silently publish immediately when scheduling is unavailable.
- Click Share once, then inspect the resulting state and wait through processing. A spinner or an accepted click is not proof of publication. If processing is slow, keep checking and update the user without clicking Share repeatedly.

## Failures and delivery

- Use fresh controls after each UI transition, especially when dialogs change. Preserve unfinished uploads when login, verification, file access or posting errors block progress. Leave identity verification to the user.
- Inspect an error before retrying. Retry only when the page indicates a recoverable failure and no publication is evident. If the same failure persists, preserve the composer, report the blocker and stop that action; do not reload away unsaved work, discard user edits or create duplicate posts.
- Require Instagram's success confirmation for a published claim, then obtain the new reel's permalink from the visible profile or post. If the permalink cannot be retrieved, report that separately rather than guessing it.
- Save a screenshot of the confirmed result beside the media when possible and embed it in the final reply. Return the permalink and a concise account of what was published, scheduled or left pending. Preserve a live page for any required handoff through the browser's documented mechanism.
